## 已实现

- 截图继续使用原有缓存，区域提取改为先裁剪再转换，避免每个检测器复制整帧。
- 普通建筑匹配缓存最终的偏移/缩放模板，保持候选类别、匹配算式和阈值不变。背景内容参与缓存键，避免复用不同背景的模板。
- 公共图片、背景和地图静态图层缓存复用。结果序号、误差和隐藏夜王提示实时绘制；返回图像与缓存分离，避免相互污染。
- 单个地图工作线程处理地形识别、建筑匹配和绘图，同一时间只保留一个任务。第一张候选完成即可显示，后续候选逐步补齐，并保留用户选择。
- 使用请求版本、游戏窗口、区域、截图会话和相关选项校验结果；过期结果不发布。程序退出时等待工作线程安全结束。
- 主悬浮窗和血条按状态变化更新；地图布局和样式按尺寸变化更新。地图隐藏且渐隐完成后停止刷新定时器，可见时只有渐变和加载动画使用较高刷新频率。
- 地图和绝招调试图片只在设置中的调试日志开启时保存，取消每张候选图之后的强制全量垃圾回收。

图片资源、建筑模板和静态地图图层分别设置 16、24、32 MiB 缓存上限，使用最近最少使用淘汰。上限合计 72 MiB，**不代表整个程序的内存上限**，不包含当前显示的图片和原有资源等。

## 离线对照

2026-09-06，Windows，i9-13900K，Python 3.13.7。同一解释器、同一组确定性合成图片；原始结果位于本地 `build/performance/baseline.json` 和 `optimized.json`。

| 场景 | 优化前重复运行中位数 | 优化后重复运行中位数 | 优化后首次运行 |
| --- | ---: | ---: | ---: |
| 2560×1440 图像提取四个区域 | 50.55 ms | 1.42 ms | 1.77 ms |
| 绘制五张 990×990 候选图 | 1336.36 ms | 13.91 ms | 1204.47 ms |
| 同一布局的建筑扫描 | 639.23 ms | 75.80 ms | 631.42 ms |

绘图和建筑扫描的主要收益来自缓存命中；首次绘图、首次扫描仍需完成实际计算。数值包含运行波动，不是游戏 FPS、原生截图耗时或整进程 CPU 占用的测量。缓存是用受控内存换取重复计算时间，不能据此声称总内存占用下降。

四个区域的像素、五张候选图的像素、建筑分类和原始匹配分数均与基线一致。另对覆盖不同地形、隐藏夜王及特殊事件的 20 张图做原版绘图对照，像素全部一致。

## 复现与回归

在项目根目录运行（先按 README 安装项目依赖）：

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_performance --output build/performance/current.json
.\.venv\Scripts\python.exe -m unittest scripts.test_performance
```

基准脚本使用合成数据，不启动游戏、截图服务或 Steam；日志写入独立的 `build/performance` 子目录。测试使用离屏 Qt，覆盖缓存边界、图像所有权、动态说明更新、重复状态合并、后台任务期间的计时、候选逐步显示、过期结果丢弃、截图重连后的结果失效和错误恢复。

仍需在游戏里对照正常游玩、反复打开地图、切屏/分辨率变化、联机场景。重点观察游戏帧时间、助手与 Helper 的 CPU/内存、首张候选显示时间以及退出是否正常。离线验证不代替这些实测。
